执行模型的一些特性会影响你编写任务的方式。提前了解这些特性，往往决定了一次运行是产出清晰的结果，还是一无所获。本页将行为约束和硬性限制集中列出；各部分的详细说明请参阅[核心概念](/zh/guides/coding-agent-optimization/overview)页面。

## 执行模型 {#execution-model}

### 每次运行都是全新的隔离沙箱 {#every-run-is-a-fresh-isolated-sandbox}

每次运行都会预配一个新的沙箱并完成初始化，运行结束后即将其销毁——参见[运行与迭代](/zh/guides/coding-agent-optimization/runs)。运行之间、任务之间不会保留任何内容：文件、已安装的软件包、环境变量和上下文都不会延续。

请确保每个[任务](/zh/guides/coding-agent-optimization/tasks)都是**自包含**的。任务不能依赖其他任务预先运行，像“使用你之前安装的 SDK”这样的指令也会失败。智能体所需的任何磁盘文件或已安装内容，都必须来自该任务的初始化文件和初始化命令，或由智能体在运行期间自行完成。

### 指令只下达一次 {#the-instruction-is-one-shot}

智能体只会接收一次任务指令，随后持续运行，直到完成任务或达到时间上限。**不支持多轮对话**——运行期间，你无法回答智能体提出的澄清问题，也无法追加消息。智能体所需的全部信息都必须写在指令中。

### 无交互式显示 {#no-interactive-display}

沙箱是**无头 Linux** 环境——没有交互式浏览器，也没有桌面 UI。设计任务时，应以智能体能通过命令行、文件系统或 HTTP 达成的结果为目标。 (系统内部会使用无头浏览器进行基于截图的评估，但它并不是供智能体使用的工具。)

### 完成工作并留下产物 {#finish-the-work-and-leave-an-artifact}

智能体进程退出后，运行即告结束，沙箱也会随即被销毁。**智能体留在后台运行的任何进程都会被终止**，其输出也随之丢失。常见的失败情形是：智能体在结束本轮时声称“开发服务器已在运行”——但服务器会随沙箱一同消失，什么也没有留下。

编写指令和目标时，应让智能体**完成工作并留下持久的产物**，而不是让进程一直保持运行：

* 让智能体将输出写入文件、捕获 HTTP 响应或保存日志，然后对该产物进行评分。
* 对于“启动服务器”类任务，应指示智能体在本次运行内依次完成启动服务器、调用服务器、将响应保存到文件、停止服务器这几个步骤。
* 对保存下来的产物进行评分 (例如使用 `bash_command` 或 `script_judge` [目标](/zh/guides/coding-agent-optimization/tasks#goals-and-criteria)) ，而不是对正在运行的进程评分。

## 硬性限制 {#hard-limits}

| 类别                | 限制                                                                                                         |
| ----------------- | ---------------------------------------------------------------------------------------------------------- |
| 智能体执行             | 每次运行最长 60 分钟 (含评估和分析在内的完整运行最长约 ~70 分钟)                                                                     |
| 初始化命令 — 长度        | 每条 1–10,000 个字符                                                                                            |
| 初始化命令 — 数量        | 任务和环境上各最多 50 条 (分别计算) ，按顺序执行并采用快速失败机制 (任一命令以非零退出码结束即中止设置)                                                  |
| 初始化命令 — 超时        | 每条 1 秒至 30 分钟 (默认 5 分钟)                                                                                    |
| 初始化命令 — 工作目录      | 必须位于 `/home/agent-user/` 下                                                                                 |
| 初始化文件 — zip 大小    | 最大 500 MB，自动解压                                                                                             |
| 初始化文件 — 目标路径      | 必须位于 `/home/agent-user/` 下                                                                                 |
| 沙箱资源              | CPU 1–4 核，内存 1–8 GB，磁盘 1–10 GB — 请参阅[环境](/zh/guides/coding-agent-optimization/environments#sandbox-resources) |
| `script_judge` 目标 | 默认超时 120 秒，可针对每个目标单独配置 (退出码 124 表示超时)                                                                      |

超出范围的沙箱资源值不会被拒绝，而是会被自动调整到允许范围内。只要请求了 GPU，运行就会自动调度到基于 GPU 的基础设施上。

## 密钥与隔离 {#secrets-and-isolation}

密钥的作用域限定在单个环境内，并在运行时以环境变量的形式注入，详见[环境](/zh/guides/coding-agent-optimization/environments#secrets-from-the-cli)。有两项限制需要注意：

* **保留名称不可覆盖。** 由平台管理的变量 (例如 `ANTHROPIC_API_KEY`、`OPENAI_API_KEY`、`AWS_*`、`HOME` 和 `PATH`) 均受保护。
* **`script_judge` 运行期间，平台密钥会被撤销**，因此验证脚本无法读取或窃取这些密钥。

出站网络访问默认处于允许状态，因为智能体运行框架需要借此访问模型提供商。

## 使用 `script_judge` {#using-script_judge}

`script_judge` [评估类型](/zh/guides/coding-agent-optimization/tasks#goals-and-criteria)会在智能体运行结束后，在沙箱中执行你自己编写的 shell 脚本 (退出码为 0 即通过) 。使用前请注意：

* 你的组织需要启用 **`script_judge` 功能标志**。如未启用，可改用确定性的替代方案 (`bash_command`、`file_exists`) 或 `llm_judge`。
* 每个脚本都会**在注册任务时接受安全审查**——凡是读取平台密钥、外泄数据、拉取并执行远程代码或耗尽资源的脚本，都会被标记。
