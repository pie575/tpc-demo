借助智能体体验功能，您可以在隔离的沙箱中让真实的编码智能体 (Claude Code、Codex 和 OpenCode) 实际使用您的产品，按照您定义的目标为每次尝试评分，并将结果转化为对文档、API 和新用户引导流程的具体改进。

如果 AI 智能体在安装您的 SDK、完成身份验证或按照文档操作时遇到困难，它们就会转而推荐其他方案。本产品会精确定位这些阻碍出现在哪里，并告诉您需要改进什么。

## 工作原理 {#how-it-works}

1. **定义任务** — 明确智能体需要借助您的产品完成什么 (例如“安装 SDK 并发送第一个事件”) ，以及判定成功的目标
2. **定义环境** — 指定由哪个智能体框架和模型来执行任务，以及任务在哪种沙箱中运行
3. **运行实验** — 在全新的沙箱中，于所有环境下并行执行每个任务
4. **查看结果** — 包括每次运行的评分、完整的运行记录、提取的信号，以及附带根本原因和修复建议的失败聚类

## 各组件如何协同工作 {#how-the-pieces-fit-together}

```text
Experiment
├── Tasks         (做什么 + 如何衡量是否成功)
├── Environments  (由哪个智能体/模型来执行)
└── Iterations    (按编号划分的运行批次)
    └── Runs      (任务 × 环境,每次运行独占一个沙箱)
        ├── 得分、通过/失败、运行记录、成本
        └── 信号值 → 按迭代汇总
```

每个概念在侧边栏的 **Core concepts** 下都有单独的页面，并在 [tpc CLI](/zh/cli/overview) 中有对应的命令组：

| 概念                                                   | 命令组                  | 常用命令                                                       |
| ---------------------------------------------------- | -------------------- | ---------------------------------------------------------- |
| [任务](/zh/guides/coding-agent-optimization/tasks)        | `tpc sim task`       | `create --file task.json`、`list`、`get`、`update`、`run`      |
| [环境](/zh/guides/coding-agent-optimization/environments) | `tpc sim env`        | `create`、`list`、`update`、`task attach/detach`、`secret set` |

## 每次运行的产出 {#what-you-get-from-each-run}

* 对照你的目标给出的通过/失败判定，以及 0–100 分的评分
* 完整的智能体运行记录：包括每条消息、每次工具调用和每个思考步骤
* 运行结束后的沙箱归档，方便你查看智能体究竟构建了什么
* Token 用量、成本和耗时
* 信号值：你在 YAML 中定义的自定义指标，会自动从运行中提取

## 通过 CLI 试用 {#try-it-from-the-cli}

借助 [tpc CLI](/zh/cli/overview)，任务及负责完成该任务的智能体都放在一个小目录中，一条命令即可运行整个流程：

```bash
# 首次设置（仅需一次）
curl -fsSL https://cli.promptingco.com/install.sh | bash
tpc auth login
```

```text
my-task/
├── task.json        # 任务内容 + 成功的评分方式
├── instruction.md   # 发给智能体的 prompt
└── environment.json # 由哪个智能体/模型执行（可选）
```

```bash
# 如有需要，先创建任务和环境，再运行——从零开始，一条命令搞定
tpc sim run ./my-task --scope pro-org/my-product
```

`tpc sim run ./my-task --scope pro-org/my-product` 是幂等的：如果匹配的任务和环境已存在，会直接复用；如果文件有变更，会进行更新；如果是新的，则会新建。因此重复运行也不会产生重复项。运行 `tpc sim spec` 可打印完整的 `task.json` 规范，运行 `tpc sim task export <task-id>` 则可将现有任务导出为类似这样的目录。

如需在相同任务上比较多个智能体，可将它们归入一个[实验](/zh/guides/coding-agent-optimization/experiments)：

```bash
tpc sim experiment create --name "Quickstart friction" --task-ids task_abc --env-ids env_1,env_2 --scope pro-org/my-product
tpc sim experiment run exp_789 --watch --scope pro-org/my-product      # 触发运行并实时跟踪至完成
tpc sim experiment results exp_789 --scope pro-org/my-product
```

所有命令均支持 `--format json`，方便在脚本中使用。以下指南分别介绍了各个抽象对应的 CLI 工作流。
