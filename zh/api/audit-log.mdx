# 审计日志 {#audit-log}

对于属于某个组织且返回 2xx 响应的非 GET 请求，TPC 会写入一条 API 审计日志条目。

## 记录内容 {#what-is-logged}

每条审计记录包含以下字段：

| 字段        | 说明                              |
| --------- | ------------------------------- |
| 组织 ID     | 根据你的凭据解析出的组织。                   |
| 用户 ID     | 凭据关联的真人用户 (如有) 。                |
| API 密钥 ID | 通过 API 密钥调用时所用的 API 密钥 ID。      |
| 主体 ID     | 服务账号 ID、API 密钥 ID、会话 ID 或用户 ID。 |
| 路由和方法     | 端点路径和 HTTP 方法。                  |
| 状态        | 响应状态码。                          |
| 认证方式      | `session`、`bearer` 或 `api_key`。 |
| 请求 ID     | `x-request-id` 响应头的值。           |
| 请求体哈希     | 请求体的 SHA-256 哈希值。               |
| 过期时间      | 该记录的保留截止时间。                     |

## 不记录的内容 {#what-is-not-logged}

TPC 不会在审计表中存储完整的请求体，只存储请求体的哈希值。这样，你既能证明使用的是哪个载荷，又无需将客户内容复制到审计记录中。

## 保留期限 {#retention}

API 审计日志记录的保留期限为 180 天。

## 查询 {#lookup}

目前尚未提供公开的审计日志端点。如需查询某个请求，请向支持团队提供 `x-request-id`、大致时间戳以及组织 slug。
