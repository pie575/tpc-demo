実行モデルには、タスクの書き方に影響する特性がいくつかあります。これらを事前に把握しておくかどうかで、実行からきれいな結果が得られるか、役に立つ成果がまったく得られないかが決まります。このページでは、動作上の制約とハードリミットを一か所にまとめています。各要素の詳細については、[コアコンセプト](/ja/guides/coding-agent-optimization/overview)の各ページを参照してください。

## 実行モデル {#execution-model}

### 実行ごとに新しい分離されたサンドボックスが使われる {#every-run-is-a-fresh-isolated-sandbox}

実行のたびに新しいサンドボックスがプロビジョニング・初期化され、実行が完了すると破棄されます。詳しくは[実行とイテレーション](/ja/guides/coding-agent-optimization/runs)を参照してください。実行間やタスク間では、ファイル、インストール済みパッケージ、環境変数、コンテキストなど、何も引き継がれません。

各[タスク](/ja/guides/coding-agent-optimization/tasks)は**自己完結型**になるように記述してください。別のタスクが先に実行されていることを前提にしたタスクは作成できません。また、「先ほどインストールした SDK を使って」のような指示は失敗します。エージェントが必要とするディスク上のファイルやインストール済みのものは、すべてタスクの Init files と Init commands で用意するか、実行中にエージェント自身に用意させる必要があります。

### 指示は一度きり {#the-instruction-is-one-shot}

エージェントはタスクの指示を一度だけ受け取り、完了するか制限時間に達するまで実行を続けます。**複数ターンのやり取りはできません**。実行中にエージェントからの確認の質問に答えたり、追加の指示を送ったりすることはできません。エージェントが必要とする情報は、すべて指示に含めてください。

### 対話型ディスプレイなし {#no-interactive-display}

サンドボックスは**ヘッドレス Linux** 環境であり、対話型のブラウザやデスクトップ UI はありません。タスクは、エージェントがコマンドライン、ファイルシステム、または HTTP 経由で達成できる成果を前提に設計してください。 (スクリーンショットによる評価のために内部でヘッドレスブラウザを使用していますが、これはエージェント用のツールではありません。)

### 作業を完了させて成果物を残す {#finish-the-work-and-leave-an-artifact}

実行はエージェントのプロセスが終了した時点で終わり、サンドボックスはその直後に破棄されます。**エージェントがバックグラウンドで動かしたままにしたプロセスはすべて強制終了され**、その出力は失われます。よくある失敗は、エージェントが「開発サーバーを起動しました」と言ってターンを終えてしまうケースです。サーバーはサンドボックスとともに停止し、何も記録されません。

エージェントがプロセスを維持し続けるのではなく、**作業を完了させて永続的な成果物を残す**ように、指示とゴールを記述してください。

* エージェントに出力をファイルへ書き込ませる、HTTP レスポンスを記録させる、またはログを保存させたうえで、その成果物を採点します。
* 「サーバーを立ち上げる」タスクでは、サーバーの起動、呼び出し、レスポンスのファイルへの保存、停止までを、すべて実行内で行うようエージェントに指示します。
* 稼働中のプロセスではなく、保存された成果物を採点します (例: `bash_command` や `script_judge` の[ゴール](/ja/guides/coding-agent-optimization/tasks#goals-and-criteria)を使用) 。

## ハードリミット {#hard-limits}

| 項目                 | 上限                                                                                                                |
| ------------------ | ----------------------------------------------------------------------------------------------------------------- |
| エージェントの実行          | 1 回の実行につき最大 60 分 (評価と分析を含めた実行全体では最大 ~70 分かかることがあります)                                                              |
| 初期化コマンド — 長さ       | 各 1～10,000 文字                                                                                                     |
| 初期化コマンド — 数        | タスクごとに最大 50 個、環境ごとに最大 50 個 (それぞれ個別にカウント) 。順番に実行され、フェイルファスト方式です (ゼロ以外の終了コードが最初に返された時点でセットアップが中止されます)               |
| 初期化コマンド — タイムアウト   | 各 1 秒～30 分 (デフォルトは 5 分)                                                                                           |
| 初期化コマンド — 作業ディレクトリ | `/home/agent-user/` 配下である必要があります                                                                                  |
| 初期化ファイル — zip サイズ  | 最大 500 MB (自動的に展開されます)                                                                                            |
| 初期化ファイル — 配置先パス    | `/home/agent-user/` 配下である必要があります                                                                                  |
| サンドボックスのリソース       | CPU 1～4、メモリ 1～8 GB、ディスク 1～10 GB — [環境](/ja/guides/coding-agent-optimization/environments#sandbox-resources)を参照してください |
| `script_judge` ゴール | タイムアウトはデフォルトで 120 秒、ゴールごとに設定可能です (終了コード 124 はタイムアウトしたことを示します)                                                     |

サンドボックスのリソース値が範囲外の場合、エラーにはならず、許容範囲内の値に自動で補正されます。GPU を 1 つでも要求すると、その実行は自動的に GPU 搭載のインフラストラクチャに割り当てられます。

## シークレットと分離 {#secrets-and-isolation}

シークレットは環境単位でスコープが設定され、実行時に環境変数として注入されます。詳しくは [環境](/ja/guides/coding-agent-optimization/environments#secrets-from-the-cli) を参照してください。注意すべき制約は次の 2 つです。

* **予約名は上書きできません。** `ANTHROPIC_API_KEY`、`OPENAI_API_KEY`、`AWS_*`、`HOME`、`PATH` など、プラットフォームが管理する変数は保護されています。
* **`script_judge` の実行中はプラットフォームのシークレットが無効化されます**。そのため、検証スクリプトがシークレットを読み取ったり外部に持ち出したりすることはできません。

外部へのネットワークアクセスはデフォルトで許可されています。これは、エージェントハーネスがモデルプロバイダーに接続するために必要なためです。

## `script_judge` の使用 {#using-script_judge}

`script_judge` [評価タイプ](/ja/guides/coding-agent-optimization/tasks#goals-and-criteria)は、エージェントの処理完了後に、独自のシェルスクリプトをサンドボックス内で実行します (終了コード 0 = 合格) 。利用する前に、次の点を確認してください。

* 組織で **`script_judge` 機能フラグ**が有効になっている必要があります。有効でない場合は、決定論的な代替手段 (`bash_command`、`file_exists`) または `llm_judge` を使用してください。
* すべてのスクリプトは、**タスクの登録時にセキュリティレビューが行われます**。プラットフォームのシークレットの読み取り、データの外部への持ち出し、リモートコードの取得と実行、リソースの枯渇を行うスクリプトにはフラグが付けられます。
