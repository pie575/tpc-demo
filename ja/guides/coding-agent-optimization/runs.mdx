**実行**とは1回の試行のことです。1つの環境が、新しいサンドボックス内で1つのタスクを実行します。**イテレーション**とは、エクスペリメント内で実行される実行の1つのまとまりです。アタッチされたすべてのタスクを、アタッチされたすべての環境で実行します。

## 実行のライフサイクル {#the-lifecycle-of-a-run}

各実行は、次のステータスを順に遷移します。

```text
queued → creating_sandbox → running → evaluating → analyzing → completed
                                                              ↘ failed
```

1. **creating&#95;sandbox** — 新しいサンドボックスがプロビジョニングされ、タスクのファイル、コマンド、シークレットを使って初期化されます
2. **running** — エージェントハーネスが指示を実行します (エージェントの実行時間の上限は 60 分です。評価と分析を含めると、実行全体で最大約 70 分かかる場合があります)
3. **evaluating** — 各目標の基準をサンドボックスとトランスクリプトに照らして検証し、スコアと合否判定を出します
4. **analyzing** — シグナルを抽出し、トランスクリプトを分析して摩擦点を洗い出します
5. **completed** — 結果が確定します。サンドボックスはアーカイブされた後、破棄されます

インフラストラクチャのステップが失敗した場合は、自動的に再試行されます。実行が `failed` とマークされるのは、再試行の上限に達した場合のみです。

## 各実行で記録される内容 {#what-each-run-records}

* **スコアと判定** — 0〜100 の総合スコアと、実行が目標を達成したかどうか
* **トランスクリプト** — エージェントのメッセージ、思考、ツール呼び出し、結果をひとつにまとめたタイムライン
* **目標ごとの結果** — 目標ごと・評価基準ごとのスコアと評価の詳細
* **サンドボックスアーカイブ** — 実行後のエージェントのホームディレクトリのスナップショット。ダウンロードして中身を確認できます
* **使用量** — トークン数、推定コスト、所要時間
* **スナップショット** — 実際に使用されたタスク定義と環境設定を、実行時点の状態で固定したもの

実行時にタスクと環境設定のスナップショットが保存されるため、過去の結果には、その結果を生んだ設定が常に正確に反映されます。後からタスクを編集しても、過去の結果が書き換えられることはありません。

## イテレーション {#iterations}

エクスペリメント内の実行は、番号付きのイテレーションにまとめられます。イテレーションはイミュータブル (変更不可) です。シグナル設定と集計結果はイテレーションの実行時点で固定されるため、イテレーション 5 とイテレーション 1 を比較する場合でも、それぞれが実行当時の状態を正確に反映していると判断できます。

イテレーションの実行契機と結果の生成方法については、[Experiments](/ja/guides/coding-agent-optimization/experiments) を参照してください。

## CLI から実行結果を確認する {#inspecting-runs-from-the-cli}

```bash
# 実行を検索する
tpc sim run list --task-id task_abc --status failed

# 特定の実行を確認する
tpc sim run get run_123        # スコア、判定、使用量、スナップショット
tpc sim run logs run_123       # 実行ログのタイムライン
tpc sim run actions run_123    # 正規化されたエージェントのアクション

# 実行またはタスク履歴をより詳しく分析する
tpc sim analysis get --run-id run_123
tpc sim analysis get --task-id task_abc
```

いずれのコマンドも `--format json` を付けて実行すると、結果をスクリプトや CI に渡せます。
