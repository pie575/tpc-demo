# 監査ログ {#audit-log}

TPC は、組織に属するリクエストのうち、2xx レスポンスを返した GET 以外のリクエストについて、API 監査ログのエントリを記録します。

## 記録される内容 {#what-is-logged}

各監査レコードには以下の情報が保存されます。

| フィールド            | 説明                                          |
| ---------------- | ------------------------------------------- |
| Organization ID  | 認証情報から特定された組織。                   |
| User ID          | 認証情報に人間のユーザーが紐づいている場合は、そのユーザー。              |
| API key ID       | API キーで呼び出した場合は、その API キー ID。               |
| Principal ID     | サービスアカウント ID、API キー ID、セッション ID、またはユーザー ID。 |
| Route and method | エンドポイントのパスと HTTP メソッド。                      |
| Status           | レスポンスのステータス。                                |
| Auth method      | `session`、`bearer`、または `api_key`。           |
| Request ID       | `x-request-id` レスポンスヘッダーの値。                 |
| Body hash        | リクエストボディの SHA-256 ハッシュ。                     |
| Expiration       | レコードの保持期限。                                  |

## 記録されない情報 {#what-is-not-logged}

TPC は、監査テーブルにリクエストボディ全体を保存しません。保存されるのはリクエストボディのハッシュのみです。そのため、顧客のコンテンツを監査証跡にコピーすることなく、どのペイロードが使用されたかを証明できます。

## 保持期間 {#retention}

API 監査ログのレコードは 180 日間保持されます。

## 照会 {#lookup}

監査ログ用の公開エンドポイントはまだ提供されていません。現時点で特定のリクエストを照会したい場合は、`x-request-id`、おおよそのタイムスタンプ、組織の slug をサポートまでお知らせください。
